# Halo —— 命令行接口契约

本文档定义 Halo 在**所有平台**上必须保持一致的命令行接口。它是把各个独立的原生实现（macOS 的 Swift、Windows 的 C/C++ 等）绑在一起的依据。

为什么需要它：Halo 走"每平台原生实现"的路线，平台之间没有共享代码。唯一能保证"一份钩子配置在任何平台行为相同"的，就是各实现都严格遵守这份接口约定。新增任何平台实现时，请以本文档为准。

## 调用形式

```
halo [--duration <秒>] [--style <rainbow|pulse>] [--color <#RRGGBB>]
```

所有参数均可选。无参数运行时，等同于 `halo --duration 3 --style rainbow`。

## 参数定义

### `--duration <秒>`

- 含义：发光持续的总时长（含淡出），单位秒
- 类型：浮点数
- 默认值：`3`
- 约束：小于 `0.3` 的值应被钳制到 `0.3`，避免一闪而过
- 时间到达后，程序必须自行退出，不得残留后台进程

### `--style <名称>`

- 含义：发光的视觉风格
- 取值：
  - `rainbow` —— 彩色流光，颜色沿屏幕边框环绕流动
  - `pulse` —— 单色呼吸，整圈边框以固定颜色明暗起伏
- 默认值：`rainbow`
- 约束：无法识别的取值应回退到 `rainbow`，不得报错退出

### `--color <#RRGGBB>`

- 含义：`pulse` 风格使用的颜色
- 格式：十六进制，七字符，以 `#` 开头，例如 `#FF3B30`
- 默认值：`#3B82F6`
- 约束：仅 `pulse` 风格使用；`rainbow` 风格忽略此参数。解析失败时回退到默认色

## 容错要求（所有平台必须遵守）

这部分是接口契约里最关键的部分，直接关系到能否被 AI 代理的钩子正确驱动。

### 1. 忽略不认识的参数

遇到未定义的参数（及其可能的值）时，必须静默忽略，继续正常运行，**不得**报错或非零退出。原因见下条。

### 2. 兼容 Codex 的 JSON 尾参

Codex CLI 通过 `notify` 钩子调用程序时，会在用户配置的参数之后，**额外追加一个 JSON 字符串作为最后一个参数**，形如：

```
{"type":"agent-turn-complete","last-assistant-message":"..."}
```

各平台实现必须能容忍这个多出来的参数。推荐做法（精确模式）：

- 若某个参数以 `{` 开头，尝试将其解析为 JSON
- 若解析成功且其中的 `type` 字段不等于 `agent-turn-complete`，则**静默退出、不发光**（说明这不是"任务完成"事件）
- 其余情况正常发光

最低要求（宽容模式）：即使不解析 JSON，也至少要做到"忽略它、照常发光"，绝不能因为这个参数崩溃。

Claude Code 的 `Stop` 钩子不追加此类参数（它通过标准输入传递数据），因此"忽略不认识的输入"这一条同时覆盖了两种代理。

## 退出行为

- 正常完成：发光结束后退出，退出码 `0`
- 因非完成事件而提前退出（见上文 JSON 判断）：退出码 `0`，不视为错误
- 程序不应长期驻留；其生命周期就是单次"启动 → 发光 → 退出"

## 行为一致性清单（移植到新平台时逐条核对）

- [ ] 无参数运行 = 彩色流光 3 秒
- [ ] `--duration` 接受浮点秒数，小于 0.3 钳制到 0.3
- [ ] `--style rainbow` / `--style pulse` 两种风格都实现
- [ ] 无法识别的 `--style` 取值回退到 `rainbow`
- [ ] `--color` 仅在 `pulse` 下生效，解析失败回退默认色
- [ ] 不认识的参数被静默忽略，不报错
- [ ] 能容忍 Codex 追加的 JSON 尾参
- [ ] JSON 中 `type != agent-turn-complete` 时静默退出（精确模式）
- [ ] 发光层鼠标穿透，不挡用户操作
- [ ] 发光层置顶，盖在普通窗口之上
- [ ] 到时自动退出，不残留进程
